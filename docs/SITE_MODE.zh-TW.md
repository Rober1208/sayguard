# 倉庫模式怎麼運作

**把同一區的攝影機整合成一張即時平面圖：每個人只算一次，距離用公尺算，同一個人只發一則警報。**

![倉庫模式：11 支攝影機整合在一張平面圖上](img/warehouse_zh.png)

## 構想

工地檢查安全帽，每支鏡頭分開看就夠了，倉庫卻不行。倉庫的鏡頭彼此重疊，同一個人常常同時出現在三、四支鏡頭裡；逐支鏡頭判斷的系統會把他算成三、四個人，警報也跟著發三、四則。「七號走道」這種管制區，每支拍得到它的鏡頭都得各畫一次。「離堆高機 3 公尺內」更麻煩，單看一張平面畫面很難判斷得準。

倉庫模式把同一區的鏡頭，當成觀察同一個空間的多個感測器。每支攝影機都對平面圖校正過，畫面裡的人和車都能換算成地面上的一個點，單位是公尺。有了地面座標，算人數、判斷有沒有進管制區、量距離，都只是簡單的幾何計算。規則看的是「人」，不是「畫面」。

## 從攝影機、平面圖到警報

```
 最多 12 支攝影機的串流
        │   同一個偵測模型批次處理：人、堆高機、托板車、搬運車、機器人
        ▼
 每支鏡頭裡的偵測框
        │   校正：畫面像素 → 地面公尺
        ▼
 平面圖上的點 ──► 工人：每人一個，跨鏡頭合併
              └─► 車輛：取它和地面接觸的位置
        │
        ▼
 以公尺定義的管制區與規則 ──► 每人每次進入一則警報 ──► 儀表板・警報紀錄・工安日報
```

- **一個偵測模型看所有鏡頭**：所有串流的畫面打包成一批，送進同一個 YOLOv8s，一次找出人和車。現成模型在這裡派不上用場：示範倉庫裡已標註的 30 台堆高機，YOLO-World 一台都沒找到；一般的 COCO 模型還把 39% 的人形機器人當成人。所以我們自己微調了一個六類的偵測模型，用 8 個訓練場景的 8,000 張圖片訓練，評估用的場景一張都沒用到。機器人有自己的類別，不會算進工人人數。
- **校正**：每支攝影機只要對平面圖校正一次，之後畫面裡地面上的任何一點，都能換算成平面圖上的位置（公尺）。示範用的是 NVIDIA 資料集附的校正資料。
- **人站在哪裡**：人的位置取腳踩在地上的那一點。貨架、推車或畫面邊緣擋住腳的時候，偵測框的底邊就不是腳；這時 SayGuard 會把頭部也投影到地面，這個人一定站在兩個投影點之間的某處。離鏡頭遠、在畫面裡很小的人，位置比較不準，計算時的權重也比較低。
- **多支鏡頭合併成一位工人**：不同鏡頭拍到的人，只要落在地面同一個位置，就是同一個人。位置取各鏡頭的加權中位數，所以單一鏡頭看歪了，也不會把人拉到幾公尺外。人走到貨架後面、暫時沒有鏡頭看到，幾秒內出來還是同一個人；一閃即逝的誤偵測，要持續一段時間才會算成一位工人。整個過程不看臉，也不用外觀模型，只靠地面上的幾何位置。
- **車輛以著地點定位**：把車輛和地面接觸的點投影到平面圖上，人和車的距離，就是人到任一支鏡頭看到的最近著地點的距離。規則只需要知道「現在這個人 3 公尺內有沒有堆高機」，所以不必分辨每一台車。
- **管制區和規則都用公尺**：管制區在平面圖上畫一次就好，不用每支鏡頭各畫一次。規則可以是有人進入某區、某區超過 N 個人、有人離某種車輛 N 公尺內，或某種車輛進入某區。規則一樣用說的：「七號走道有人停留超過5秒就通知我」或「Tell me if an AMR enters aisle seven」，SayGuard 會整理成一張規則卡片讓工安人員確認。卡片上會列出拍得到這個區域的鏡頭；如果沒有任何鏡頭拍得到，規則就無法啟用。
- **每人每次進入一則警報**：條件要持續一段時間才算數（堆高機規則是 2 秒）。成立之後，不管幾支鏡頭看到，同一個人只發一則警報；他如果一直待著，冷卻時間會拉開提醒的間隔。離開管制區一陣子再回來，算新的一次進入，會再提醒一次。追蹤編號可能幾十秒就換一個，所以發警報前，系統會先判斷「新出現的人」是不是剛剛才提醒過的那位。下一個走進同一條走道的人，還是會另外發一則警報。

儀表板上即時跑的，和下面評估用的是同一套程式，評估時再拿結果和標準答案比對。

## 工安人員看到什麼

- **即時平面圖**：和各鏡頭畫面並排，顯示管制區、攝影機位置、每位工人（圓點，警報中變紅）和車輛。有人太靠近車輛時，會畫一條紅線並標出距離幾公尺。
- **一個可信的人數**：「現場人數」每人只算一次，旁邊列出各鏡頭直接相加的數字，兩者差多少一眼就看得出來。
- **同一個人，每支鏡頭都標出來**：警報中的工人，在每支拍到他的鏡頭裡都會框成紅色。警報卡片附上快照、規則、區域，以及拍到他的鏡頭。
- **規則用說的**：「用說的加規則」面板接受國語或英文，用講的、打字都可以。
- **不顯示編號，也不露臉**：儀表板只計數、發警報，不顯示編號。所有畫面和快照都會把人臉打上馬賽克，影像不出現場。
- **工安日報**：和工地模式一樣，從同一份警報紀錄產生。

## 實測結果

測試用的是 NVIDIA PhysicalAI-SmartSpaces 的六棟合成倉庫，每棟 3 到 11 支攝影機，偵測模型從沒用這些建築訓練過。每段影片約五分鐘，逐格和 NVIDIA 提供的標準答案（每個人真實的地面位置）比對。以下數據在 PC 原型（RTX 5060 Ti）上測得。

| | 六棟測試倉庫 |
|---|---|
| 人數平均誤差 | **0.05–1.74 人**；各鏡頭直接相加最多差 60.09 人（實際 22.0 人算成 82.09 人） |
| 地面位置平均誤差 | **0.173–0.26 公尺** |
| 人到堆高機的距離，誤差中位數 | **0.2–0.47 公尺** |
| 門口與碼頭區 | **53/53** 次進入都有涵蓋（100%），52 則警報 **0** 則誤報 |
| 離堆高機 3 公尺規則 | **56/61** 個事件有涵蓋（92%），26 則警報 1 則誤報 |
| 走道・作業區 | 進入事件涵蓋 **83%**・**96%**；誤報佔警報的 4%・7% |
| 同樣的偵測結果，改成逐支鏡頭發警報 | 管制區涵蓋大幅下降：示範倉庫碼頭區只剩 36.4%，倉庫模式是 100% |
| 一句話變成完全正確的倉庫規則（打字輸入的句子） | 在沒拿來調整的測試句上 **84–88%**；只靠 LLM 只有 16–24% |

*涵蓋*：這次進入有自己的警報，或同一條規則剛提醒過這個人，冷卻時間內刻意不再重複。

各場景的完整表格和每個數字怎麼量，請見 [docs/results](results/README.zh-TW.md) 的「倉庫模式」一節。

## 部署規格

- **每個最多 12 支攝影機的區域，配一台 UGen300。** 建築比較大，就切成幾個區域，各自有平面圖、攝影機和盒子。
- **每個要監看的管制區，至少要有兩支鏡頭拍得到**，而且站著的人在畫面裡至少 40 px 高（1280×720）。

架設一個區域只要三步：每支攝影機對平面圖校正一次、在平面圖上畫管制區、用說的加規則。

規格的由來：六棟測試倉庫（3 到 11 支攝影機）都在規格內；唯一超出規格的是一個 16 支攝影機的場景，結果也是所有場景裡最差的。人在畫面中 40–80 px 高時偵測率是 92%，20–40 px 時降到 68%；一個區域有兩支鏡頭，貨架擋住其中一支的視線時，另一支可以補上。

分工：UGen300 負責所有鏡頭的偵測（一次批次處理），以及語音規則用的 Whisper 和 Qwen2.5。主機負責解碼串流、平面圖的幾何計算、跨鏡頭合併、規則判斷和儀表板，這些都不需要額外的模型。

## 限制

- **目前只有合成影片**：所有數字都來自電腦合成的倉庫影片，真實攝影機會在 Stage II 到 ASUS 的測試場地實測。
- **需要校正**：每支攝影機都要做一次地面校正，SayGuard 目前還沒有自己的校正工具。
- **兩棟倉庫的堆高機**：六棟測試倉庫裡有兩棟，偵測模型只在 11.5% 和 16.9% 有堆高機的畫面中找到它。之後打算用客戶自己的車輛畫面再微調。
- **編號維持不久**：同一位工人的編號可能幾十秒就換一個。警報仍然以人為單位，但畫面不顯示編號；工人走進另一個區域，也會拿到新編號。
- **開放區域人多時會重複提醒**：示範倉庫的開放作業區裡，每個觸發警報的進入事件平均發了 2.93 則警報。
- **還沒在 UGen300 上跑**：倉庫偵測模型已經編譯成 Hailo-10H 的 HEF（960×960 和 544×960 兩種），準確率也在 Hailo 的 INT8 模擬器上確認過，但還沒上過實機。它的處理量，以及一台盒子接 12 支攝影機撐不撐得住，要到 Stage II 第 1 週才量得到（[HAILO_PORT.zh-TW.md](HAILO_PORT.zh-TW.md)）。

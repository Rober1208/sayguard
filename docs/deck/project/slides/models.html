This table is the feasibility argument. Every job maps to a model Hailo already publishes for Hailo-10H; the warehouse detector uses the same YOLOv8s architecture and is already compiled for the chip, with INT8 matching float in the emulator. That row is our own build, not a Hailo figure, so it has no frame rate yet; we measure it in the first week of Stage II. The language model runs only on demand, when someone speaks a rule or the daily report is planned, and our code calls it through the Ollama API, which hailo-ollama serves on the UGen300; on the PC a rule takes well under a second, and from Hailo’s reference speeds we estimate about eleven seconds for the language-model step on the UGen300, which is fine for a rule the officer confirms. Both detectors are compiled to HEFs; they and the CLIP encoder were quantized to INT8 and checked in Hailo’s INT8 emulator, which models the chip’s integer arithmetic, and scored the same way as the float models. Nothing has run on hardware yet.
